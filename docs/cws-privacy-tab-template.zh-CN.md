# Chrome Web Store 隐私页填写示例（Draw.io AI Sidebar）

用于 Chrome Web Store 后台 隐私权 标签页填写参考。

## 1) Single purpose（单一用途）

建议填写：

本扩展用于在 app.diagrams.net 中提供 AI 辅助绘图能力。用户通过自然语言描述、可选图片或截图标注，生成 draw.io XML，并可一键注入当前画布以完成流程图编辑。

## 2) Permission justification（权限说明）

建议按权限逐项填写：

1. storage
用于保存本地配置（如模型地址、API Key、模型列表）以及历史对话和 XML 版本记录。

2. tabs
用于在当前标签页识别扩展运行上下文，支持截图与交互流程。

3. activeTab
用于在用户主动操作时对当前活动标签页执行功能。

4. scripting
用于在 app.diagrams.net 页面读取当前图表 XML 及注入生成后的 XML。

5. host_permissions: https://app.diagrams.net/*
仅在该站点注入内容脚本并执行与画布交互相关功能。

## 3) Remote code（远程代码）

建议选择：

No, I am not using remote code

说明：

本扩展不从远程地址下载并执行扩展代码。扩展通过网络请求你配置的模型 API，以获取文本/XML 生成结果。

## 4) Data usage disclosures（数据使用披露）

如后台复选项涉及以下类别，可按实际勾选并说明：

1. 用户输入文本（提示词）
用途：发送到用户配置的模型接口生成图表 XML。

2. 用户提供内容（图片/截图标注）
用途：作为多模态上下文发送到模型接口。

3. 网站内容（当前画布 XML）
用途：基于现有图表进行修改生成。

4. 身份验证信息/凭据（API Key）
用途：用于调用用户配置的模型服务；保存于本地。

5. 扩展活动数据（历史记录、版本记录）
用途：本地展示多轮对话与版本回退。

## 5) Privacy policy URL（最关键）

必须把隐私政策链接填在后台指定字段（不是写在说明里）。

建议流程：

1. 将隐私政策页面发布为公开 HTTPS 链接（可访问、无需登录）。
2. 在隐私权标签页的 Privacy policy URL 字段填写该链接。
3. 确保页面内容与后台勾选项一致。

## 6) 审核前快速自检

1. 隐私政策链接可公开访问且长期有效。
2. 政策中明确写出 收集什么、用于什么、共享给谁。
3. 后台披露项与实际代码一致。
4. 权限解释与功能一一对应，不多报用途。
5. 重新提交新草稿后再等待审核。
